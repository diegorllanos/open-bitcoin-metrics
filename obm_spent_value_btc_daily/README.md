# Open Bitcoin Metrics: Daily Spent Output Value in BTC

This repository provides the following time series of the **Open Bitcoin Metrics (OBM)** project:

```text
obm_spent_value_btc_daily
```

The series reports the total daily BTC value of outputs spent by non-coinbase transaction inputs, exported from the persistent OBM spent-output indexer database.

The exporter script is:

```text
export_obm_spent_value_btc_daily.py
```

It reads the SQLite database generated by:

```text
obm_spent_output_indexer.py
```

The spent-output indexer itself is documented separately. This README focuses only on the metric-specific exporter.

## Metric summary

| Field | Value |
|---|---|
| Series identifier | `obm_spent_value_btc_daily` |
| Display name | Daily spent output value in BTC |
| Unit | `BTC` |
| Frequency | `daily` |
| Time convention | UTC calendar day |
| Source layer | Exported from `obm_spent_output_indexer.sqlite` |
| External data required | No |
| Main use | Spent-output activity, denominator for dormancy, UTXO-flow analysis |

## Definition

`obm_spent_value_btc_daily` measures the total BTC value of previous outputs consumed by non-coinbase transaction inputs in blocks assigned to a given UTC calendar day.

For each non-coinbase transaction input `i`, let:

```text
ValueBTC_i
```

be the BTC value of the previous output spent by that input.

Daily spent output value is obtained by summing these previous-output values over all non-coinbase inputs included in blocks assigned to UTC calendar day `d`:

```text
SpentValueBTC_d = sum_i ValueBTC_i
```

where the sum is taken over all spent outputs assigned to day `d`.

## Interpretation

`obm_spent_value_btc_daily` measures the gross BTC value of outputs consumed on-chain each day.

This metric is useful for:

- measuring raw spent-output activity;
- constructing dormancy as CDD divided by spent value;
- comparing transaction count with BTC value spent;
- analyzing UTXO turnover;
- studying periods of high movement of previously unspent outputs;
- building derived spent-output and coin-age indicators.

The metric should not be interpreted as entity-adjusted payment volume, exchange-adjusted transfer volume, or final economic settlement value. Bitcoin transactions often include change outputs, self-transfers, batching, consolidation, custodial operations, and internal wallet management. As a result, raw spent-output value can exceed economically meaningful payment value.

## Relationship with the spent-output indexer

This metric is exported from the table:

```text
daily_aggregates
```

in the SQLite database produced by:

```text
obm_spent_output_indexer.py
```

The relevant source column is:

```text
spent_value_sats
```

The indexer stores daily spent value internally as satoshis:

```text
spent_value_sats = sum(value_sats_i)
```

over all previous outputs spent by non-coinbase transaction inputs assigned to the UTC date.

The exporter converts satoshis to BTC:

```text
value = spent_value_sats / 100000000
```

The exporter does not query Bitcoin Core. It only reads the already generated indexer database and writes a standard OBM CSV file.

## Data format

The CSV file follows the standard OBM schema:

```text
date,series_id,value,unit,frequency,release_version
```

Example:

```csv
date,series_id,value,unit,frequency,release_version
2024-01-01,obm_spent_value_btc_daily,428318.49281735,BTC,daily,OBM v0.1.0
2024-01-02,obm_spent_value_btc_daily,391204.18290472,BTC,daily,OBM v0.1.0
```

### Columns

| Column | Description |
|---|---|
| `date` | UTC calendar date in `YYYY-MM-DD` format |
| `series_id` | Stable OBM identifier: `obm_spent_value_btc_daily` |
| `value` | Total BTC value of spent previous outputs on that day |
| `unit` | Measurement unit: `BTC` |
| `frequency` | Observation frequency: `daily` |
| `release_version` | OBM dataset release version inherited from the indexer metadata |

## Reproducibility

The metric is generated by reading the persistent OBM spent-output indexer database.

For each date in the requested interval, the exporter:

1. opens the SQLite database generated by `obm_spent_output_indexer.py`;
2. verifies that the database metadata identify it as an OBM spent-output indexer database;
3. verifies that the requested ending date is not beyond the maximum processed date recorded by the indexer;
4. reads the `spent_value_sats` value from `daily_aggregates`;
5. exports zero if a requested date has no row in `daily_aggregates`;
6. converts satoshis to BTC by dividing by 100,000,000;
7. writes the resulting time series to CSV using the standard OBM schema;
8. optionally generates a plot.

The blockchain scan and previous-output resolution are performed by the shared spent-output indexer. This exporter is a deterministic transformation from the indexer database to the OBM CSV format.

## Typical script usage

Generate the CSV file:

```bash
python3 export_obm_spent_value_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --output data/daily/obm_spent_value_btc_daily.csv
```

Generate the CSV file and a plot:

```bash
python3 export_obm_spent_value_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --output data/daily/obm_spent_value_btc_daily.csv \
  --plot \
  --plot_output figures/obm_spent_value_btc_daily.png
```

If `--plot_output` is omitted while `--plot` is used, the plot is saved next to the CSV file with a `.png` extension.

## Command-line arguments

| Argument | Description |
|---|---|
| `--start_date` | Starting UTC date, inclusive, in `YYYY-MM-DD` format |
| `--end_date` | Ending UTC date, inclusive, in `YYYY-MM-DD` format |
| `--state_db` | Path to the SQLite database generated by `obm_spent_output_indexer.py` |
| `--output` | Output CSV file path |
| `--release_version` | Fallback release version if the indexer database does not contain one |
| `--plot` | Generate a plot of the exported series |
| `--plot_output` | Output path for the plot |

If the indexer database contains `release_version` metadata, the exporter uses that value. Otherwise, it uses the fallback value passed through `--release_version`.

## Requirements

The exporter assumes:

- an existing SQLite database generated by `obm_spent_output_indexer.py`;
- Python 3;
- SQLite through Python's standard library;
- `matplotlib`, only if plot generation is requested.

This exporter does not require:

- a running Bitcoin Core node;
- access to the Bitcoin Core JSON-RPC interface;
- direct block scanning;
- direct previous-output reconstruction at export time;
- address extraction;
- user clustering;
- entity identification;
- external price data;
- third-party APIs.

The heavy blockchain processing is performed by the spent-output indexer before this exporter is run.

## Missing-date convention

If a requested date has no row in `daily_aggregates`, the exporter writes:

```text
0.00000000
```

for that date.

This convention is appropriate for spent value because it is a daily flow variable. If no spent-output aggregate is assigned to a UTC date under the indexer's timestamp convention, total spent value for that date is zero.

This differs from ratio metrics. For example, dormancy is computed as:

```text
CDD / spent value
```

and is undefined when spent value is zero. By contrast, spent value itself can be equal to zero.

## Precision

The indexer stores spent output values internally as integer satoshis. The exporter converts this value to BTC and writes values with eight decimal places:

```text
value = spent_value_sats / 100000000
```

This preserves the standard Bitcoin monetary precision.

## Validation

The following internal checks are performed or recommended:

- verify that `--start_date` is not later than `--end_date`;
- verify that the SQLite state database exists;
- verify that the database metadata contain the expected `indexer_id`;
- verify that the database contains processed-date metadata;
- verify that `--end_date` is not later than the maximum date processed by the indexer;
- verify that every requested date appears exactly once in the output;
- check that all exported values are non-negative;
- verify that dormancy satisfies `obm_dormancy_days_daily = obm_cdd_btcxdays_daily / obm_spent_value_btc_daily` for dates with positive spent value;
- compare selected periods with independent public spent-value or transfer-value series as diagnostics.

External comparisons should be interpreted cautiously because providers may differ in timestamp convention, transfer-value definition, change-output treatment, entity adjustment, historical edge-case handling, and whether the metric is based on spent outputs or economically adjusted transfers.

## Relationship with other OBM metrics

This metric is closely related to:

```text
obm_cdd_btcxdays_daily
obm_dormancy_days_daily
obm_bincdd365d_btc_daily
obm_spent_output_count_daily
```

The main derived relationship is dormancy:

```text
obm_dormancy_days_daily =
    obm_cdd_btcxdays_daily /
    obm_spent_value_btc_daily
```

for dates where spent value is positive.

The metric is also related to age-threshold spent-value series, such as:

```text
obm_bincdd365d_btc_daily
```

which counts only spent outputs whose age is at least 365 days.

## Known limitations

Take into account that this metric:

- is exported from the OBM spent-output indexer database;
- depends on the correctness and completeness of the indexer run;
- inherits the UTC block-timestamp convention of the indexer;
- is a raw spent-output metric, not an entity-adjusted transfer-volume metric;
- includes self-transfers, change-related activity, batching, and consolidation transactions;
- does not identify users, entities, exchanges, custodians, or payment purpose;
- reports BTC value, not fiat-denominated value;
- may change if the underlying indexer definition or release version changes.

Despite these limitations, `obm_spent_value_btc_daily` is a core OBM series. It provides a transparent raw measure of BTC-denominated spent-output activity and serves as a foundation for dormancy, age-band spent-value metrics, and broader UTXO-flow analysis.
