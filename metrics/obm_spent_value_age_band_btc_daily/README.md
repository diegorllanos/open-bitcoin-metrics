# Open Bitcoin Metrics: Daily Spent Output Value by Age Band in BTC

This repository provides the following wide daily table of the **Open Bitcoin Metrics (OBM)** project:

```text
obm_spent_value_age_band_btc_daily
```

The table reports the daily BTC value of spent outputs split by output-age band. It is exported from the persistent OBM spent-output indexer database.

The exporter script is:

```text
export_obm_spent_value_age_band_btc_daily.py
```

A standalone plotting utility is also available:

```text
plot_obm_spent_value_age_band_btc_daily.py
```

The exporter reads the SQLite database generated by:

```text
obm_spent_output_indexer.py
```

The spent-output indexer itself is documented separately. This README focuses only on the metric-specific exporter and its output table.

## Metric summary

| Field | Value |
|---|---|
| Series identifier | `obm_spent_value_age_band_btc_daily` |
| Display name | Daily spent output value by age band in BTC |
| Unit | `BTC` |
| Frequency | `daily` |
| Time convention | UTC calendar day |
| Source layer | Exported from `obm_spent_output_indexer.sqlite` |
| External data required | No |
| Output shape | Wide table, one row per date, one column per age band |
| Main use | Age composition of spent value, UTXO-flow analysis, validation of threshold metrics |

## Definition

`obm_spent_value_age_band_btc_daily` decomposes total daily spent output value by the age of the outputs at the moment they are spent.

For each spent output `i`, let:

```text
ValueBTC_i
```

be the BTC value of the previous output being spent, and let:

```text
AgeDays_i
```

be the age of that previous output, measured as the elapsed time in days between the block in which the output was created and the block in which it is spent.

For each UTC day `d` and age band `k`, the metric reports:

```text
SpentValueAgeBandBTC_{d,k}
    = sum_i ValueBTC_i * 1{AgeDays_i belongs to band k}
```

where the sum is taken over all outputs spent in blocks assigned to UTC calendar day `d`.

The unit is:

```text
BTC
```

This metric is not a scalar daily series. It is a wide daily age-band table: each row corresponds to one UTC date, and each age-band column contains the BTC value of spent outputs assigned to that band.

## Age-band convention

The exporter uses the following fixed age bands:

| Age-band label | Output column |
|---|---|
| `0d_1d` | `spent_value_0d_1d_btc` |
| `1d_1w` | `spent_value_1d_1w_btc` |
| `1w_1m` | `spent_value_1w_1m_btc` |
| `1m_3m` | `spent_value_1m_3m_btc` |
| `3m_6m` | `spent_value_3m_6m_btc` |
| `6m_1y` | `spent_value_6m_1y_btc` |
| `1y_2y` | `spent_value_1y_2y_btc` |
| `2y_3y` | `spent_value_2y_3y_btc` |
| `3y_5y` | `spent_value_3y_5y_btc` |
| `5y_7y` | `spent_value_5y_7y_btc` |
| `7y_10y` | `spent_value_7y_10y_btc` |
| `10y_plus` | `spent_value_10y_plus_btc` |

These labels must match the labels stored by `obm_spent_output_indexer.py` in the `daily_age_band_aggregates.age_band` field.

## Interpretation

`obm_spent_value_age_band_btc_daily` shows how daily spent output value is distributed across output-age cohorts.

This metric is useful for:

- decomposing total spent value by output age;
- distinguishing young-output turnover from older-coin movement;
- identifying dormant-supply activation episodes;
- studying long-term-holder and short-term-holder activity under explicit age thresholds;
- validating threshold metrics such as `obm_cdd_155d_btc_daily` and `obm_cdd_365d_btc_daily`;
- constructing age-band shares of total spent value;
- building empirical datasets in which the age composition of spent value is relevant.

The metric should not be interpreted as entity-adjusted payment volume, user activity, exchange-adjusted transfer volume, or economically meaningful settlement value. It is a raw spent-output measure. It includes self-transfers, change-related activity, batching, wallet consolidation, exchange operations, and custodial wallet management through the underlying spent-output structure.

## Relationship with the spent-output indexer

This metric is exported from the table:

```text
daily_age_band_aggregates
```

in the SQLite database produced by:

```text
obm_spent_output_indexer.py
```

The relevant source fields are:

```text
date
age_band
spent_value_sats
```

The indexer stores age-band spent value internally as satoshis:

```text
spent_value_sats = sum(value_sats_i for outputs assigned to age band k)
```

for each date and age band.

The exporter converts satoshis to BTC:

```text
value_btc = spent_value_sats / 100000000
```

The exporter does not query Bitcoin Core. It only reads the already generated indexer database and writes a wide OBM CSV table.

## Data format

Unlike scalar OBM series, this table does not use a single `value` column. Instead, it uses one column per age band.

The CSV file follows this schema:

### Columns

| Column | Description |
|---|---|
| `date` | UTC calendar date in `YYYY-MM-DD` format |
| `series_id` | Stable OBM identifier: `obm_spent_value_age_band_btc_daily` |
| `spent_value_*_btc` | BTC value of spent outputs assigned to the corresponding age band |

| `release_version` | OBM dataset release version inherited from the indexer metadata |

## Reproducibility

The metric is generated by reading the persistent OBM spent-output indexer database.

For each date in the requested interval, the exporter:

1. opens the SQLite database generated by `obm_spent_output_indexer.py`;
2. verifies that the database metadata identify it as an OBM spent-output indexer database;
3. verifies that the requested ending date is not beyond the maximum processed date recorded by the indexer;
4. reads `date`, `age_band`, and `spent_value_sats` from `daily_age_band_aggregates`;
5. initializes all age-band columns to zero for each requested date;
6. fills each available date-band pair using the corresponding `spent_value_sats` value;
7. writes zero for missing date-band pairs;
8. converts satoshis to BTC by dividing by 100,000,000;
9. writes one wide row per UTC date;
10. optionally validates that the sum across age-band columns equals total spent value from `daily_aggregates.spent_value_sats`;
11. optionally generates a stacked area plot.

The blockchain scan, previous-output resolution, output-age computation, and age-band assignment are performed by the shared spent-output indexer. This exporter is a deterministic transformation from the indexer database to a wide OBM CSV table.

## Typical exporter usage

Generate the CSV file:

```bash
python3 export_obm_spent_value_age_band_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --output data/daily/obm_spent_value_age_band_btc_daily.csv
```

Generate the CSV file with row-sum validation:

```bash
python3 export_obm_spent_value_age_band_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --output data/daily/obm_spent_value_age_band_btc_daily.csv \
  --validate_row_sums
```

Generate the CSV file and a stacked area plot:

```bash
python3 export_obm_spent_value_age_band_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --output data/daily/obm_spent_value_age_band_btc_daily.csv \
  --validate_row_sums \
  --plot \
  --plot_output figures/obm_spent_value_age_band_btc_daily.png
```

If `--plot_output` is omitted while `--plot` is used, the plot is saved next to the CSV file with a `.png` extension.

## Standalone plotting utility

The standalone plot script `plot_obm_spent_value_age_band_btc_daily.py`, available at the `tools` directory of
this repository, reads an already generated CSV file and produces the same stacked area plot:

```bash
python3 plot_obm_spent_value_age_band_btc_daily.py \
  data/daily/obm_spent_value_age_band_btc_daily.csv \
  --output figures/obm_spent_value_age_band_btc_daily.png
```

The plotting utility does not compute the metric. It validates the expected wide CSV columns and then generates a stacked area chart where the filled areas represent the contribution of each age band to total daily spent output value.

## Requirements

The exporter assumes:

- an existing SQLite database generated by `obm_spent_output_indexer.py`;
- Python 3;
- SQLite through Python's standard library;
- `matplotlib`, only if plot generation is requested.

The plot-only utility assumes:

- Python 3;
- an existing wide `obm_spent_value_age_band_btc_daily` CSV file;
- `matplotlib`.

Neither script requires:

- a running Bitcoin Core node;
- access to the Bitcoin Core JSON-RPC interface;
- direct block scanning;
- direct previous-output reconstruction at export time;
- address extraction;
- user clustering;
- entity identification;
- external price data;
- third-party APIs.

The heavy blockchain processing is performed by the spent-output indexer before this exporter is run.

## Missing-date and missing-band convention

For each requested date, the exporter creates one complete row with all age-band columns.

If a date-band pair is absent from `daily_age_band_aggregates`, the exporter writes:

```text
0.00000000
```

for that age-band column.

This convention is appropriate because each age-band value is a daily flow variable. If no spent-output value is assigned to an age band on a given UTC date, the value for that band is zero.

## Precision

The indexer stores age-band spent output values internally as integer satoshis. The exporter converts each value to BTC and writes values with eight decimal places:

```text
value_btc = spent_value_sats / 100000000
```

This preserves the standard Bitcoin monetary precision.

## Validation

Validation is divided into two groups: checks performed directly by the exporter or plot-only utility, and additional checks that are advisable for release preparation or independent auditing.

### Checks performed by the exporter

The exporter performs the following checks during execution:

- verifies that `--start_date` is not later than `--end_date`;
- verifies that the SQLite state database exists;
- opens the SQLite database in read-only mode;
- verifies that the database metadata contain the expected `indexer_id`;
- verifies that the database contains the required processing metadata, including `last_processed_height`, `last_processed_date`, and `max_processed_date`;
- verifies that the `daily_age_band_aggregates` table exists;
- verifies that `daily_age_band_aggregates` contains the required columns `date`, `age_band`, and `spent_value_sats`;
- verifies that the requested `--end_date` is not later than the maximum date processed by the indexer;
- initializes every requested date with all expected age bands set to zero;
- rejects unexpected age-band labels found in the indexer database;
- rejects duplicate date-band aggregates;
- rejects negative `spent_value_sats` values;
- converts satoshis to BTC by dividing by 100,000,000;
- writes one complete wide row per requested date;
- writes the output using the documented wide OBM schema;
- when `--validate_row_sums` is used, verifies that the sum across all age-band columns equals `daily_aggregates.spent_value_sats` for each date, within the configured tolerance;
- optionally generates a stacked area plot when `--plot` is used.

These checks ensure that the exporter is reading from the expected indexer database, that the requested interval is covered by the indexer, that all age-band labels are known, and that the generated CSV has one complete row per date.

### Checks performed by the plot-only utility

The standalone plotting utility performs the following checks:

- verifies that the input CSV file exists;
- verifies that the CSV file is non-empty;
- verifies that all expected wide-table columns are present;
- verifies that every row has `series_id = obm_spent_value_age_band_btc_daily`;
- verifies that every row has `unit = BTC`;
- verifies that every row has `frequency = daily`;
- verifies that all age-band values are present and parseable as decimals;
- rejects negative age-band values;
- rejects duplicate dates;
- sorts observations chronologically before plotting;
- generates a stacked area plot using all age-band columns.

### Recommended additional checks

The following checks are not performed automatically in all workflows, but are recommended before publishing a release or using the table in empirical work:

- verify that every requested date appears exactly once in the output CSV;
- verify that all age-band values are non-negative;
- run the exporter with `--validate_row_sums` whenever `daily_aggregates.spent_value_sats` is available;
- verify that the sum across all age-band columns equals `obm_spent_value_btc_daily` for every date when both are exported from the same indexer database and release version;
- verify that threshold metrics can be reconstructed from the appropriate age-band columns where thresholds align exactly with the band definitions;
- inspect unusually large spikes in old age bands and confirm that they correspond to large old-output movements;
- inspect unusually large spikes in young age bands and compare them with transaction-count and spent-output-count metrics;
- check that the `release_version` field is consistent with the indexer metadata and with other OBM series generated from the same release;
- document any differences observed when comparing this table with external spent-output age distribution or supply-age analytics.

The main internal consistency relation is:

```text
sum of all age-band columns = obm_spent_value_btc_daily
```

for every UTC date, provided that both datasets are generated from the same indexer database and release version.

External comparisons should be interpreted cautiously because providers may differ in timestamp convention, age-band boundaries, entity adjustment, change-output treatment, transfer-value definition, and historical edge-case handling.

## Relationship with other OBM metrics

This table is closely related to:

```text
obm_spent_value_btc_daily
obm_spent_output_count_daily
obm_cdd_btcxdays_daily
obm_dormancy_days_daily
obm_cdd_155d_btc_daily
obm_cdd_365d_btc_daily
obm_spent_value_lt155d_btc_daily
```

The primary relationship is:

```text
obm_spent_value_btc_daily =
    spent_value_0d_1d_btc
  + spent_value_1d_1w_btc
  + spent_value_1w_1m_btc
  + spent_value_1m_3m_btc
  + spent_value_3m_6m_btc
  + spent_value_6m_1y_btc
  + spent_value_1y_2y_btc
  + spent_value_2y_3y_btc
  + spent_value_3y_5y_btc
  + spent_value_5y_7y_btc
  + spent_value_7y_10y_btc
  + spent_value_10y_plus_btc
```

for each date, subject to matching definitions and release versions.

The table can be used to build age-band shares:

```text
spent_value_age_band_btc / obm_spent_value_btc_daily
```

for dates where total spent value is positive.

It can also be used to interpret threshold metrics. For example, the 365-day threshold metric should be closely related to the sum of age bands beginning at one year, provided that the band boundary and threshold convention match exactly.

## Known limitations

Take into account that this metric:

- is exported from the OBM spent-output indexer database;
- depends on the correctness and completeness of the indexer run;
- inherits the UTC block-timestamp convention of the indexer;
- inherits the age computation and age-band assignment conventions used by the indexer;
- uses fixed age-band boundaries;
- is a raw spent-output table, not an entity-adjusted measure;
- includes self-transfers, change-related activity, batching, consolidation transactions, exchange operations, and custodial wallet management;
- does not identify users, entities, exchanges, custodians, or payment purpose;
- reports BTC value, not fiat-denominated value;
- is a wide vector-valued daily table rather than a scalar `value` series;
- may change if the underlying indexer definition, age-band convention, or release version changes.

Despite these limitations, `obm_spent_value_age_band_btc_daily` is a useful OBM age-distribution table. It provides a transparent decomposition of daily spent output value by output age and complements scalar spent-value, CDD, dormancy, and threshold-based coin-age metrics.
