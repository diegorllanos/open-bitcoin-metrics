# Open Bitcoin Metrics: Daily Miner Revenue in BTC

This repository provides the following time series of the **Open Bitcoin Metrics (OBM)** project:

```text
obm_miner_revenue_btc_daily
```

The series reports daily BTC-denominated miner revenue, exported from the persistent OBM spent-output indexer database.

The exporter script is:

```text
export_obm_miner_revenue_btc_daily.py
```

It reads the SQLite database generated by:

```text
obm_spent_output_indexer.py
```

The spent-output indexer itself is documented separately. This README focuses only on the metric-specific exporter.

## Metric summary

| Field | Value |
|---|---|
| Series identifier | `obm_miner_revenue_btc_daily` |
| Display name | Daily miner revenue in BTC |
| Unit | `BTC` |
| Frequency | `daily` |
| Time convention | UTC calendar day |
| Source layer | Exported from `obm_spent_output_indexer.sqlite` |
| External data required | No |
| Main use | Miner compensation, security-budget analysis, fee and issuance decomposition |

## Definition

`obm_miner_revenue_btc_daily` measures the total BTC paid to miners through coinbase transactions in blocks assigned to a given UTC calendar day.

For each block `b`, miner revenue in BTC is the total output value of the coinbase transaction:

```text
MinerRevenueBTC_b = CoinbaseOutputBTC_b
```

Daily miner revenue is obtained by summing this quantity over all blocks assigned to UTC calendar day `d`:

```text
MinerRevenueBTC_d = sum_b CoinbaseOutputBTC_b
```

where the sum is taken over all blocks assigned to day `d`.

The coinbase transaction pays miners two components:

```text
MinerRevenueBTC_d = IssuanceBTC_d + FeesBTC_d
```

where:

- `IssuanceBTC_d` is newly created BTC;
- `FeesBTC_d` is BTC paid by users as transaction fees.

## Interpretation

`obm_miner_revenue_btc_daily` measures BTC-denominated miner compensation before costs.

This metric is useful for:

- studying miner incentives;
- analyzing the BTC-denominated security budget;
- decomposing miner compensation into issuance and fees;
- studying halving events and subsidy reductions;
- computing the fee share of miner revenue;
- comparing miner revenue dynamics with transaction demand and block-space usage.

The metric should not be interpreted as miner profit. It does not account for electricity costs, hardware depreciation, pool fees, financing costs, taxes, or other operating expenses. It is also not fiat-denominated miner income, because it reports miner revenue in BTC rather than USD, EUR, or any other fiat currency.

## Relationship with the spent-output indexer

This metric is exported from the table:

```text
daily_aggregates
```

in the SQLite database produced by:

```text
obm_spent_output_indexer.py
```

The relevant source column is:

```text
coinbase_output_sats
```

The indexer stores miner revenue internally as satoshis:

```text
coinbase_output_sats = sum of coinbase transaction output values
```

over all blocks assigned to the UTC date.

The exporter converts satoshis to BTC:

```text
value = coinbase_output_sats / 100000000
```

The exporter does not query Bitcoin Core. It only reads the already generated indexer database and writes a standard OBM CSV file.

## Data format

The CSV file follows the standard OBM schema:

```text
date,series_id,value,unit,frequency,release_version
```

Example:

```csv
date,series_id,value,unit,frequency,release_version
2024-01-01,obm_miner_revenue_btc_daily,931.13492017,BTC,daily,OBM v0.1.0
2024-01-02,obm_miner_revenue_btc_daily,892.19278145,BTC,daily,OBM v0.1.0
```

### Columns

| Column | Description |
|---|---|
| `date` | UTC calendar date in `YYYY-MM-DD` format |
| `series_id` | Stable OBM identifier: `obm_miner_revenue_btc_daily` |
| `value` | Total BTC paid to miners through coinbase transactions on that day |
| `unit` | Measurement unit: `BTC` |
| `frequency` | Observation frequency: `daily` |
| `release_version` | OBM dataset release version inherited from the indexer metadata |

## Reproducibility

The metric is generated by reading the persistent OBM spent-output indexer database.

For each date in the requested interval, the exporter:

1. opens the SQLite database generated by `obm_spent_output_indexer.py`;
2. verifies that the database metadata identify it as an OBM spent-output indexer database;
3. verifies that the requested ending date is not beyond the maximum processed date recorded by the indexer;
4. reads the `coinbase_output_sats` value from `daily_aggregates`;
5. exports zero if a requested date has no row in `daily_aggregates`;
6. converts satoshis to BTC by dividing by 100,000,000;
7. writes the resulting time series to CSV using the standard OBM schema;
8. optionally generates a plot.

The blockchain scan, coinbase-output aggregation, previous-output resolution, and fee reconstruction are performed by the shared spent-output indexer. This exporter is a deterministic transformation from the indexer database to the OBM CSV format.

## Typical script usage

Generate the CSV file:

```bash
python3 export_obm_miner_revenue_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --output data/daily/obm_miner_revenue_btc_daily.csv
```

Generate the CSV file and a plot:

```bash
python3 export_obm_miner_revenue_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --output data/daily/obm_miner_revenue_btc_daily.csv \
  --plot \
  --plot_output figures/obm_miner_revenue_btc_daily.png
```

If `--plot_output` is omitted while `--plot` is used, the plot is saved next to the CSV file with a `.png` extension.

## Command-line arguments

| Argument | Description |
|---|---|
| `--start_date` | Starting UTC date, inclusive, in `YYYY-MM-DD` format |
| `--end_date` | Ending UTC date, inclusive, in `YYYY-MM-DD` format |
| `--state_db` | Path to the SQLite database generated by `obm_spent_output_indexer.py` |
| `--output` | Output CSV file path |
| `--release_version` | Fallback release version if the indexer database does not contain one |
| `--plot` | Generate a plot of the exported series |
| `--plot_output` | Output path for the plot |

If the indexer database contains `release_version` metadata, the exporter uses that value. Otherwise, it uses the fallback value passed through `--release_version`.

## Requirements

The exporter assumes:

- an existing SQLite database generated by `obm_spent_output_indexer.py`;
- Python 3;
- SQLite through Python's standard library;
- `matplotlib`, only if plot generation is requested.

This exporter does not require:

- a running Bitcoin Core node;
- access to the Bitcoin Core JSON-RPC interface;
- direct block scanning;
- direct previous-output reconstruction at export time;
- address extraction;
- user clustering;
- entity identification;
- external price data;
- third-party APIs.

The heavy blockchain processing is performed by the spent-output indexer before this exporter is run.

## Indexer coverage assumption

The OBM spent-output indexer is designed to be built from the Bitcoin genesis block onward. Therefore, this exporter assumes that the indexer database contains a complete historical pass from block height 0 through the maximum processed height recorded in the metadata.

Under this invariant, a missing row in `daily_aggregates` for a requested UTC date does not indicate an unprocessed date. It indicates that no block-level aggregate activity was assigned to that date under the indexer's timestamp convention. For `obm_miner_revenue_btc_daily`, such dates are therefore exported as zero.

Users should not use this exporter with a partially initialized or truncated indexer database unless they first verify that the requested date interval is fully covered.

## Missing-date convention

If a requested date has no row in `daily_aggregates`, the exporter writes:

```text
0.00000000
```

for that date.

This convention is appropriate for miner revenue because miner revenue is a daily flow variable. If no block-level aggregate activity is assigned to a UTC date under the indexer's timestamp convention, total BTC-denominated miner revenue for that date is zero.

This differs from ratio metrics. For example, fee share of miner revenue is computed as:

```text
fees / (issuance + fees)
```

and is undefined when the denominator is zero. By contrast, miner revenue itself can be equal to zero.

## Precision

The indexer stores coinbase output values internally as integer satoshis. The exporter converts this value to BTC and writes values with eight decimal places:

```text
value = coinbase_output_sats / 100000000
```

This preserves the standard Bitcoin monetary precision.

## Validation

The following internal checks are performed or recommended:

- verify that `--start_date` is not later than `--end_date`;
- verify that the SQLite state database exists;
- verify that the database metadata contain the expected `indexer_id`;
- verify that the database contains processed-date metadata;
- verify that `--end_date` is not later than the maximum date processed by the indexer;
- verify that every requested date appears exactly once in the output;
- check that all exported values are non-negative;
- verify that `obm_miner_revenue_btc_daily = obm_issuance_btc_daily + obm_fees_btc_daily` when all three series are exported from the same indexer database;
- verify that `obm_fees_btc_daily = obm_miner_revenue_btc_daily - obm_issuance_btc_daily` as an equivalent consistency check;
- compare selected periods with independent public miner-revenue or block-reward series as diagnostics.

External comparisons should be interpreted cautiously because providers may differ in timestamp convention, confirmation policy, chain-reorganization handling, treatment of underclaimed issuance, treatment of historical edge cases, and whether values are reported in BTC or fiat currency.

## Relationship with other OBM metrics

This metric is closely related to:

```text
obm_issuance_btc_daily
obm_fees_btc_daily
obm_fee_share_revenue_ratio_daily
```

The main identity is:

```text
obm_miner_revenue_btc_daily =
    obm_issuance_btc_daily + obm_fees_btc_daily
```

The fee-share ratio is derived as:

```text
obm_fee_share_revenue_ratio_daily =
    obm_fees_btc_daily /
    obm_miner_revenue_btc_daily
```

or equivalently:

```text
obm_fee_share_revenue_ratio_daily =
    obm_fees_btc_daily /
    (obm_issuance_btc_daily + obm_fees_btc_daily)
```

for dates where the denominator is positive.

## Aggregation to lower frequencies

Because miner revenue is a flow variable, monthly miner revenue should be computed as the sum of the corresponding daily values:

```text
MinerRevenueBTC_m = sum of MinerRevenueBTC_d over all days d in month m
```

It should not be computed as an average of daily miner revenue values unless the research question specifically concerns average daily miner revenue within the month.

## Known limitations

Take into account that this metric:

- is exported from the OBM spent-output indexer database;
- depends on the correctness and completeness of the indexer run;
- inherits the UTC block-timestamp convention of the indexer;
- reports miner revenue in BTC, not fiat currency;
- does not measure miner profit, mining costs, electricity costs, hardware depreciation, pool fees, or operating margins;
- does not measure the distribution of revenue across miners or mining pools;
- is not entity-adjusted and does not identify the miner or pool associated with each block;
- may change if the underlying indexer definition or release version changes.

Despite these limitations, `obm_miner_revenue_btc_daily` is a core OBM series. It provides a transparent and reproducible BTC-denominated measure of daily miner compensation and supports research on miner incentives, halving dynamics, the security budget, and the transition from issuance-based to fee-based miner revenue.
