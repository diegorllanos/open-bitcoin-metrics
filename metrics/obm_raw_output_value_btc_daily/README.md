# Open Bitcoin Metrics: Daily Raw Output Value in BTC

This repository provides the following time series of the **Open Bitcoin Metrics (OBM)** project:

```text
obm_raw_output_value_btc_daily
```

The series reports the daily BTC value of outputs created by non-coinbase transactions, exported from the persistent OBM spent-output indexer database.

The exporter script is:

```text
export_obm_raw_output_value_btc_daily.py
```

It reads the SQLite database generated by:

```text
obm_spent_output_indexer.py
```

## Metric summary

| Field | Value |
|---|---|
| Series identifier | `obm_raw_output_value_btc_daily` |
| Display name | Daily raw output value in BTC |
| Unit | `BTC` |
| Frequency | `daily` |
| Time convention | UTC calendar day |
| Source layer | Exported from `obm_spent_output_indexer.sqlite` |
| External data required | No |
| Main use | Raw on-chain output activity, transaction-output volume, gross settlement diagnostics |

## Definition

`obm_raw_output_value_btc_daily` measures the total BTC value of outputs created by non-coinbase transactions in blocks assigned to a given UTC calendar day.

For each non-coinbase transaction `j`, let:

```text
OutputValueBTC_j
```

be the sum of the BTC values of all outputs created by that transaction.

Daily raw output value is:

```text
RawOutputValueBTC_d =
    sum_j OutputValueBTC_j
```

where the sum is taken over all non-coinbase transactions included in blocks assigned to UTC date `d`.

Coinbase transaction outputs are excluded. Therefore, this metric measures ordinary transaction-output creation and does not include miner subsidy or fee payments created through the coinbase transaction.

The unit is:

```text
BTC
```

## Interpretation

`obm_raw_output_value_btc_daily` is a raw transaction-output value metric.

This metric is useful for:

- measuring gross non-coinbase output creation;
- studying raw on-chain settlement activity;
- complementing spent-output value, transaction fees, and transaction count;
- comparing transaction-output volume with spent-input volume;
- constructing diagnostic checks based on transaction accounting identities;
- studying broad changes in transaction-output behavior.

The metric should not be interpreted as entity-adjusted transfer volume, economic payment volume, user activity, exchange-adjusted flow, or final settlement between distinct economic agents. It includes change outputs, self-transfers, batching, wallet reorganizations, exchange and custodial internal movements, and other raw output activity visible on-chain.

## Relationship with the spent-output indexer

This metric is exported from the table:

```text
daily_aggregates
```

or another user-specified daily aggregate table in the SQLite database produced by:

```text
obm_spent_output_indexer.py
```

The exporter uses the transaction accounting identity:

```text
fee = input value - output value
```

For non-coinbase transactions, this can be rearranged as:

```text
output value = input value - fee
```

Aggregated by UTC date:

```text
raw_output_value = spent_value - fees
```

The preferred source columns are integer satoshi-denominated columns, for example:

```text
spent_value_sats
fees_sats
```

or equivalent columns such as:

```text
total_spent_value_sats
total_fees_sats
```

The exporter computes:

```text
raw_output_value_sats = spent_value_sats - fees_sats
```

and converts the result to BTC:

```text
value = raw_output_value_sats / 100000000
```

If satoshi-denominated columns are not available, BTC-denominated columns can be used as a fallback, although integer satoshi columns are preferred for exactness.

The exporter does not query Bitcoin Core. It only reads the already generated indexer database and writes a standard OBM CSV file.

## Data format

The CSV file follows the standard OBM schema:

```text
date,series_id,value,unit,frequency,release_version
```

Example:

```csv
date,series_id,value,unit,frequency,release_version
2024-01-01,obm_raw_output_value_btc_daily,1283912.12345678,BTC,daily,OBM v0.1.0
2024-01-02,obm_raw_output_value_btc_daily,1175401.91827364,BTC,daily,OBM v0.1.0
```

### Columns

| Column | Description |
|---|---|
| `date` | UTC calendar date in `YYYY-MM-DD` format |
| `series_id` | Stable OBM identifier: `obm_raw_output_value_btc_daily` |
| `value` | Daily raw non-coinbase output value |
| `unit` | Measurement unit: `BTC` |
| `frequency` | Observation frequency: `daily` |
| `release_version` | OBM dataset release version |

## Reproducibility

The metric is generated by reading the persistent OBM spent-output indexer database.

For each date in the requested interval, the exporter:

1. opens the SQLite database generated by `obm_spent_output_indexer.py`;
2. identifies the daily aggregate table, either automatically or through `--table`;
3. identifies the date column, either automatically or through `--date_column`;
4. identifies the spent-value and fee columns, either automatically or through `--spent_value_column` and `--fees_column`;
5. prefers satoshi-denominated columns when `--value_mode auto` is used;
6. reads the spent-value and fee values for the requested date interval;
7. computes `raw_output_value = spent_value - fees`;
8. rejects negative raw-output values as inconsistent;
9. optionally exports zero when a requested date has no aggregate row and `--missing_dates_as_zero` is used;
10. writes the resulting time series to CSV using the standard OBM schema;
11. optionally generates a plot.

The blockchain scan, previous-output resolution, spent-value computation, and fee computation are performed by the shared spent-output indexer. This exporter is a deterministic transformation from the indexer database to the OBM CSV format.

## Typical script usage

Generate the CSV file using the default indexer database path:

```bash
python3 export_obm_raw_output_value_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --missing_dates_as_zero \
  --output data/daily/obm_raw_output_value_btc_daily.csv
```

Generate the CSV file and a plot:

```bash
python3 export_obm_raw_output_value_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --missing_dates_as_zero \
  --output data/daily/obm_raw_output_value_btc_daily.csv \
  --plot \
  --plot_output figures/obm_raw_output_value_btc_daily.png
```

If `--plot_output` is omitted while `--plot` is used, the plot is saved next to the CSV file with a `.png` extension.

Specify table and column names explicitly when the database schema uses non-default names:

```bash
python3 export_obm_raw_output_value_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --table daily_aggregates \
  --date_column date \
  --spent_value_column spent_value_sats \
  --fees_column fees_sats \
  --value_mode sats \
  --missing_dates_as_zero \
  --output data/daily/obm_raw_output_value_btc_daily.csv
```

## Command-line arguments

| Argument | Description |
|---|---|
| `--start_date` | Starting UTC date, inclusive, in `YYYY-MM-DD` format |
| `--end_date` | Ending UTC date, inclusive, in `YYYY-MM-DD` format |
| `--state_db` | Path to the SQLite database generated by `obm_spent_output_indexer.py` |
| `--table` | Daily aggregate table name; if omitted, the exporter attempts auto-detection |
| `--date_column` | Date column name; if omitted, the exporter attempts auto-detection |
| `--spent_value_column` | Column containing daily spent output value |
| `--fees_column` | Column containing daily transaction fees |
| `--value_mode` | Interpretation of the spent-value and fee columns: `auto`, `sats`, or `btc` |
| `--missing_dates_as_zero` | Export zero for requested dates absent from the aggregate table |
| `--output` | Output CSV file path |
| `--release_version` | Dataset release version written to the output |
| `--plot` | Generate a plot of the exported series |
| `--plot_output` | Output path for the plot |
| `--quiet` | Suppress diagnostic messages printed to standard error |

The default state database is:

```text
cache/obm_spent_output_indexer.sqlite
```

The default output file is:

```text
obm_raw_output_value_btc_daily.csv
```

The default value mode is:

```text
auto
```

In `auto` mode, the exporter first tries to use satoshi-denominated columns. If it cannot find them, it tries BTC-denominated columns.

## Requirements

The exporter assumes:

- an existing SQLite database generated by `obm_spent_output_indexer.py`;
- Python 3;
- SQLite through Python's standard library;
- `matplotlib`, only if plot generation is requested.

This exporter does not require:

- a running Bitcoin Core node;
- access to the Bitcoin Core JSON-RPC interface;
- direct block scanning;
- direct previous-output reconstruction at export time;
- address clustering;
- entity identification;
- external price data;
- third-party APIs.

The heavy blockchain processing is performed by the spent-output indexer before this exporter is run.

## Missing-date convention

The argument:

```text
--missing_dates_as_zero
```

controls how the exporter handles requested dates that have no row in the daily aggregate table.

Without this argument, missing dates are treated as suspicious. The exporter stops with an error because it cannot distinguish between:

```text
1. a genuinely empty date under the indexer's timestamp convention
2. an incomplete or inconsistent indexer database
3. a date outside the processed range
4. an unexpected schema or export problem
```

With `--missing_dates_as_zero`, the exporter writes:

```text
0.00000000
```

for requested dates with no aggregate row.

This convention is appropriate for `obm_raw_output_value_btc_daily` when the indexer database is known to fully cover the requested interval. Under that condition, an absent daily aggregate row means that no relevant aggregate was assigned to that UTC date in the indexer database. Since raw output value is a flow variable, such dates can be exported as zero.

This is especially useful in early Bitcoin history, where some UTC dates may have no blocks or no relevant non-coinbase output activity under the OBM block-timestamp convention.

However, users should be cautious. If the database is incomplete, `--missing_dates_as_zero` can hide a coverage problem by converting missing aggregate rows into zeros. For debugging, schema checks, or partial indexer runs, it is safer to omit this argument and let the exporter fail on missing dates.

Recommended usage:

```text
Use --missing_dates_as_zero for full historical OBM releases
after verifying that the indexer database fully covers the requested interval.
```

Do not use it as a substitute for verifying indexer completeness.

## Precision

When satoshi-denominated columns are used, the exporter computes the metric using integer arithmetic:

```text
raw_output_value_sats = spent_value_sats - fees_sats
```

The exporter then converts satoshis to BTC:

```text
value = raw_output_value_sats / 100000000
```

and writes values with eight decimal places.

When BTC-denominated columns are used, the exporter relies on decimal arithmetic. This is supported for flexibility, but satoshi-denominated columns are preferred because they avoid rounding ambiguity.

## Validation

Validation is divided into two groups: checks actually performed by the exporter script, and additional checks recommended for release preparation or independent auditing.

### Checks performed by the script

The exporter performs the following checks during execution:

- verifies that `--start_date` is not later than `--end_date`;
- verifies that the SQLite state database specified through `--state_db` exists;
- verifies that the daily aggregate table exists when `--table` is supplied;
- attempts to auto-detect the daily aggregate table when `--table` is omitted;
- verifies that the date column exists when `--date_column` is supplied;
- attempts to auto-detect the date column when `--date_column` is omitted;
- verifies that the spent-value column exists when `--spent_value_column` is supplied;
- verifies that the fees column exists when `--fees_column` is supplied;
- attempts to auto-detect spent-value and fee columns when explicit column names are omitted;
- prefers satoshi-denominated columns when `--value_mode auto` is used;
- falls back to BTC-denominated columns in `auto` mode when satoshi-denominated columns are not found;
- verifies that satoshi-denominated values are integers when `--value_mode sats` or an auto-detected satoshi mode is used;
- verifies that numeric values can be parsed as valid decimals;
- verifies that each returned date appears at most once;
- computes `raw_output_value = spent_value - fees`;
- rejects any date for which `raw_output_value` is negative;
- detects requested dates missing from the aggregate table;
- raises an error for missing dates unless `--missing_dates_as_zero` is supplied;
- writes `0.00000000` for missing dates when `--missing_dates_as_zero` is supplied;
- writes one output row per requested UTC date;
- writes the output using the standard OBM schema;
- optionally generates a plot when `--plot` is used.

These checks ensure that the exporter uses a coherent table and column selection, applies the transaction-accounting identity consistently, and prevents negative raw-output values from being silently exported.

### Recommended additional checks

The following checks are not performed automatically by the script, but are recommended before publishing a release or using the series in empirical work:

- verify that the indexer database was built from the Bitcoin genesis block onward, as assumed by OBM exporters;
- verify that the requested interval is fully covered by the indexer database;
- verify that the database metadata contain the expected `indexer_id`, if metadata are available;
- verify that the database contains processed-date or processed-height metadata, if available;
- verify that `--end_date` is not later than the maximum date processed by the indexer;
- verify that every requested date appears exactly once in the output CSV;
- check that all exported values are non-negative;
- use `--missing_dates_as_zero` only after confirming that missing rows represent zero flow rather than incomplete indexer coverage;
- compare selected dates with the direct block-scanning implementation as a diagnostic;
- compare selected periods with independent public data providers as diagnostics;
- verify consistency with the identity:
  ```text
  spent_value = raw_output_value + fees
  ```
  up to formatting precision;
- compare the exported series with `obm_spent_value_btc_daily` and `obm_fees_btc_daily` generated from the same indexer run;
- inspect unusually large observations to distinguish genuine raw output activity from exchange reshuffling, wallet consolidation, batching, or other non-payment activity.

External comparisons should be interpreted cautiously because providers may differ in timestamp convention, coinbase exclusion, treatment of change outputs, entity-adjustment heuristics, and the exact definition of transaction volume.

## Relationship with other OBM metrics

This metric is closely related to the following OBM metrics:

```text
obm_spent_value_btc_daily
obm_fees_btc_daily
obm_tx_count_daily
obm_spent_output_count_daily
obm_block_weight_wu_daily
```

The most important accounting identity is:

```text
obm_raw_output_value_btc_daily =
    obm_spent_value_btc_daily - obm_fees_btc_daily
```

provided that all three series are computed from the same indexer run and use the same UTC block-timestamp convention.

Equivalently:

```text
obm_spent_value_btc_daily =
    obm_raw_output_value_btc_daily + obm_fees_btc_daily
```

This identity is useful for validation and for understanding the difference between input-side and output-side raw transaction value.

## Indexer coverage assumption

The OBM spent-output indexer is designed to be built from the Bitcoin genesis block onward. Therefore, the exporter assumes that the indexer database contains a complete historical pass from block height 0 through the maximum processed height recorded in the metadata.

Under this invariant, a missing row in the daily aggregate table for a requested date does not necessarily indicate an unprocessed date. It may indicate that no relevant aggregate was assigned to that UTC date under the indexer's timestamp convention.

For `obm_raw_output_value_btc_daily`, such dates may be exported as zero when `--missing_dates_as_zero` is used.

Users should not use this exporter with a partially initialized or truncated indexer database unless they first verify that the requested date interval is fully covered.

## Known limitations

Take into account that this metric:

- is exported from the OBM spent-output indexer database;
- depends on the correctness and completeness of the indexer run;
- inherits the UTC block-timestamp convention of the indexer;
- is a raw transaction-output value metric, not an entity-adjusted transfer-volume metric;
- excludes coinbase outputs;
- includes change outputs, self-transfers, batching, wallet reorganizations, exchange and custodial internal movements, and other raw output activity;
- does not measure users, addresses, entities, payments, or economic intent;
- depends on the accounting identity `output value = spent value - fees`;
- may differ from provider metrics that apply entity adjustment, change-output filtering, or different transaction-volume definitions;
- may change if the underlying indexer definition or release version changes.

Despite these limitations, `obm_raw_output_value_btc_daily` is a useful OBM raw activity series. It provides a transparent and reproducible measure of non-coinbase transaction-output value and supports research on raw on-chain volume, settlement activity, and transaction-accounting relationships.
