# Open Bitcoin Metrics: Daily Raw Output Value in BTC

This repository provides the following time series of the **Open Bitcoin Metrics (OBM)** project:

```text
obm_raw_output_value_btc_daily
```

The series reports the total daily BTC value of outputs created by non-coinbase transactions. It is computed directly from Bitcoin blocks obtained through Bitcoin Core RPC.

The computation script is:

```text
compute_obm_raw_output_value_btc_daily.py
```

## Metric summary

| Field | Value |
|---|---|
| Series identifier | `obm_raw_output_value_btc_daily` |
| Display name | Daily raw output value in BTC |
| Unit | `BTC` |
| Frequency | `daily` |
| Time convention | UTC calendar day |
| Source layer | Direct Bitcoin Core block scan |
| External data required | No |
| Coinbase outputs included | No |
| Main use | Raw transaction-output activity, transaction-value proxy, comparison with spent-value metrics |

## Definition

`obm_raw_output_value_btc_daily` measures the total BTC value of outputs created by non-coinbase transactions in blocks assigned to a given UTC calendar day.

Let `B_d` denote the set of blocks assigned to UTC date `d`. For each non-coinbase transaction `j` included in a block `b` in `B_d`, let `O_j` denote the set of outputs created by that transaction. Let `v_o` denote the BTC value of output `o`.

The metric is defined as:

```text
RawOutputValueBTC_d =
    sum over b in B_d
    sum over non-coinbase transactions j in b
    sum over outputs o in O_j
    v_o
```

Coinbase transaction outputs are excluded. This is important because coinbase output value represents miner revenue, which is already covered by miner-revenue and issuance-related OBM metrics.

A block is assigned to a UTC calendar date using its block timestamp as returned by Bitcoin Core:

```text
d(b) = UTCDate(block_time_b)
```

The unit is:

```text
BTC
```

## Interpretation

`obm_raw_output_value_btc_daily` is a raw transaction-output value metric. It measures the total BTC value appearing in outputs of non-coinbase transactions assigned to each UTC day.

This metric is useful for:

- measuring raw on-chain output activity;
- complementing transaction count and spent-output value;
- constructing transaction-output-based activity proxies;
- comparing output-side and input-side activity;
- supporting studies that use raw transaction volume or transfer-value proxies;
- interpreting large movements in apparent on-chain value.

The metric should not be interpreted as clean economic transfer volume. It includes change outputs, self-transfers, batching, wallet reorganizations, exchange operations, custodial wallet management, and other raw output activity visible on-chain. For that reason, the series is named **raw output value**, not payment volume or economic volume.

## Relationship with other OBM metrics

This metric is closely related to:

```text
obm_tx_count_daily
obm_spent_value_btc_daily
obm_spent_output_count_daily
obm_fees_btc_daily
obm_miner_revenue_btc_daily
```

The key distinction is between output-side and input-side measures.

`obm_raw_output_value_btc_daily` sums newly created outputs of non-coinbase transactions:

```text
sum of non-coinbase transaction outputs
```

whereas `obm_spent_value_btc_daily` sums previous outputs consumed by transaction inputs:

```text
sum of spent previous outputs
```

At the transaction level, for non-coinbase transactions:

```text
input value = output value + transaction fee
```

Therefore, over a day, and subject to the same block assignment convention:

```text
obm_spent_value_btc_daily
    approximately equals
obm_raw_output_value_btc_daily + obm_fees_btc_daily
```

when all three series are computed over the same set of non-coinbase transactions and release version.

This relationship can be used as an internal consistency check, although exact comparison requires the same timestamp convention, transaction inclusion convention, and handling of early historical edge cases.

## Data source and input requirements

The metric is computed directly from a running Bitcoin Core full node through the JSON-RPC interface.

For each block in the selected interval, the script retrieves the decoded block using:

```text
getblock <block_hash> 2
```

The script reads transaction outputs directly from the decoded block. It does not need to resolve transaction inputs to previous outputs.

This metric requires:

- a synchronized Bitcoin Core full node;
- JSON-RPC access to the node;
- access to decoded block data.

This metric does not require:

- the OBM spent-output indexer database;
- `txindex=1`;
- previous-output reconstruction;
- address extraction;
- user clustering;
- entity identification;
- external price data;
- third-party APIs.

Although `txindex=1` is useful for other OBM metrics, it is not required here because all needed output data are available from decoded blocks.

## Reproducibility

The metric is generated by scanning blocks in a date interval and summing output values from non-coinbase transactions.

For each selected date interval, the script:

1. connects to Bitcoin Core through JSON-RPC;
2. obtains the current chain tip using `getblockchaininfo`;
3. identifies an approximate block-height interval covering the requested UTC dates;
4. expands the interval using `--height_margin`;
5. scans every block in the expanded interval;
6. assigns each block to a UTC calendar date using the block timestamp;
7. skips blocks outside the requested date interval;
8. skips each block's coinbase transaction;
9. sums the values of all outputs in non-coinbase transactions;
10. initializes all requested calendar dates to zero;
11. writes one row per UTC date using the standard OBM schema;
12. optionally generates a plot.

The height-margin expansion is used because Bitcoin block timestamps are not strictly monotonic with respect to block height. The expanded scan interval reduces the risk of missing boundary blocks whose timestamps fall inside the selected UTC dates.

## Typical script usage

Generate the CSV file using Bitcoin Core cookie authentication:

```bash
python3 compute_obm_raw_output_value_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --use_default_cookie \
  --output data/daily/obm_raw_output_value_btc_daily.csv
```

Generate the CSV file and a plot:

```bash
python3 compute_obm_raw_output_value_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --use_default_cookie \
  --output data/daily/obm_raw_output_value_btc_daily.csv \
  --plot \
  --plot_output figures/obm_raw_output_value_btc_daily.png
```

Generate the CSV file using explicit RPC credentials:

```bash
python3 compute_obm_raw_output_value_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --rpc_url http://127.0.0.1:8332 \
  --rpc_user my_rpc_user \
  --rpc_password my_rpc_password \
  --output data/daily/obm_raw_output_value_btc_daily.csv
```

RPC credentials can also be supplied through environment variables:

```bash
export BITCOIN_RPC_URL="http://127.0.0.1:8332"
export BITCOIN_RPC_USER="my_rpc_user"
export BITCOIN_RPC_PASSWORD="my_rpc_password"
```

Then run:

```bash
python3 compute_obm_raw_output_value_btc_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --output data/daily/obm_raw_output_value_btc_daily.csv
```

## Command-line arguments

| Argument | Description |
|---|---|
| `--start_date` | Starting UTC date, inclusive, in `YYYY-MM-DD` format |
| `--end_date` | Ending UTC date, inclusive, in `YYYY-MM-DD` format |
| `--rpc_url` | Bitcoin Core RPC URL |
| `--rpc_user` | Bitcoin Core RPC username |
| `--rpc_password` | Bitcoin Core RPC password |
| `--cookie_path` | Path to Bitcoin Core RPC cookie file |
| `--use_default_cookie` | Use the default cookie path `~/.bitcoin/.cookie` |
| `--rpc_timeout` | RPC timeout in seconds |
| `--height_margin` | Extra blocks scanned before and after the approximate height interval |
| `--output` | Output CSV file path |
| `--release_version` | Dataset release version written to the output |
| `--plot` | Generate a plot of the resulting series |
| `--plot_output` | Output path for the plot |
| `--quiet` | Suppress diagnostic messages printed to standard error |

The default output file is:

```text
obm_raw_output_value_btc_daily.csv
```

The default release version is:

```text
OBM v0.1.0
```

The default height margin is:

```text
288 blocks
```

This corresponds to approximately two days of expected Bitcoin block production.

## Data format

The output CSV file follows the standard OBM scalar schema:

```text
date,series_id,value,unit,frequency,release_version
```

Example:

```csv
date,series_id,value,unit,frequency,release_version
2024-01-01,obm_raw_output_value_btc_daily,587321.12345678,BTC,daily,OBM v0.1.0
2024-01-02,obm_raw_output_value_btc_daily,493810.00000000,BTC,daily,OBM v0.1.0
```

### Columns

| Column | Description |
|---|---|
| `date` | UTC calendar date in `YYYY-MM-DD` format |
| `series_id` | Stable OBM identifier: `obm_raw_output_value_btc_daily` |
| `value` | Total BTC value of outputs created by non-coinbase transactions |
| `unit` | Measurement unit: `BTC` |
| `frequency` | Observation frequency: `daily` |
| `release_version` | OBM dataset release version |

## Missing-date convention

The script initializes every requested UTC date to zero before scanning blocks.

If no non-coinbase output value is assigned to a selected UTC date, the script writes:

```text
0.00000000
```

This convention is appropriate because the metric is a daily flow variable.

## Precision

Bitcoin Core returns transaction-output values in BTC. The script converts each output value to integer satoshis using Python's `Decimal` type, accumulates daily totals in satoshis, and then converts the final daily sum back to BTC.

The output is written with eight decimal places:

```text
value = raw_output_value_sats / 100000000
```

This preserves the standard Bitcoin monetary precision.

## Validation

Validation is divided into two groups: checks performed directly by the script, and additional checks that are advisable for release preparation or independent auditing.

### Checks performed by the script

The script performs the following checks during execution:

- verifies that `--start_date` is not later than `--end_date`;
- verifies that `--height_margin` is non-negative;
- verifies that the RPC authentication configuration is valid;
- verifies that the RPC cookie file exists and has valid format when cookie authentication is used;
- connects to Bitcoin Core through JSON-RPC;
- obtains the current chain tip using `getblockchaininfo`;
- locates an approximate block-height interval for the requested timestamp range;
- expands the scan interval using `--height_margin`;
- scans all blocks in the expanded interval;
- assigns each scanned block to a UTC date using the block timestamp;
- counts only blocks whose UTC date lies inside the requested interval;
- skips coinbase transactions;
- verifies that each counted transaction output has a value field;
- converts output values to satoshis using decimal arithmetic;
- initializes all selected UTC dates with zero;
- writes one output row per selected UTC date;
- writes the output using the standard OBM schema;
- optionally generates a plot when `--plot` is used;
- prints diagnostics including counted blocks, non-coinbase transactions, and outputs, unless `--quiet` is used.

These checks ensure that the script scans a sufficiently broad block interval, excludes coinbase outputs, preserves one row per selected date, and uses exact Bitcoin monetary precision.

### Recommended additional checks

The following checks are not performed automatically by the script, but are recommended before publishing a release or using the series in empirical work:

- verify that every requested date appears exactly once in the output CSV;
- verify that all exported values are non-negative;
- verify that early dates with no non-coinbase transactions have zero raw output value;
- compare the number of counted non-coinbase transactions with `obm_tx_count_daily`, adjusting for whether that series includes or excludes coinbase transactions;
- compare the relationship:
  ```text
  obm_spent_value_btc_daily
      approximately equals
  obm_raw_output_value_btc_daily + obm_fees_btc_daily
  ```
  when all series are computed from the same blocks and release version;
- inspect unusually large daily spikes and confirm that they correspond to large raw output activity;
- compare selected periods with independent blockchain explorers or data providers as diagnostics;
- document any differences observed when comparing this raw metric with external transaction-volume or transfer-volume series.

External comparisons should be interpreted cautiously because providers may differ in timestamp convention, coinbase treatment, change-output treatment, entity adjustment, transfer-value definition, and chain-reorganization handling.

## Known limitations

Take into account that this metric:

- is a raw output-value metric, not an entity-adjusted economic transfer-volume metric;
- includes change outputs;
- includes self-transfers;
- includes batching effects;
- includes exchange and custodial internal movements;
- includes wallet consolidation and reorganization activity;
- excludes coinbase outputs by definition;
- depends on the block timestamp convention used to assign blocks to UTC dates;
- does not identify users, entities, payment purpose, exchanges, custodians, or change outputs;
- reports BTC value, not fiat-denominated value;
- is directly computed from decoded blocks and does not require the spent-output indexer;
- may differ from commercial transaction-volume metrics that use heuristics to remove change, self-transfers, or entity-internal flows.

Despite these limitations, `obm_raw_output_value_btc_daily` is a useful OBM activity series. It provides a transparent, full-node-derived measure of raw output-side value creation by non-coinbase transactions and complements transaction count, spent value, fees, and age-based spent-output metrics.
