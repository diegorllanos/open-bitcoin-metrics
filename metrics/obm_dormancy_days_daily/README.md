# Open Bitcoin Metrics: Daily Dormancy

This repository provides the following time series of the **Open Bitcoin Metrics (OBM)** project:

```text
obm_dormancy_days_daily
```

The series reports daily Bitcoin dormancy, measured in days, exported from the persistent OBM spent-output indexer database.

The exporter script is:

```text
export_obm_dormancy_days_daily.py
```

It reads the SQLite database generated by:

```text
obm_spent_output_indexer.py
```

The spent-output indexer itself is documented separately. This README focuses only on the metric-specific exporter.

## Metric summary

| Field | Value |
|---|---|
| Series identifier | `obm_dormancy_days_daily` |
| Display name | Daily dormancy |
| Unit | `days` |
| Frequency | `daily` |
| Time convention | UTC calendar day |
| Source layer | Exported from `obm_spent_output_indexer.sqlite` |
| External data required | No |
| Main use | Average age of spent value, coin-age analysis, dormant-supply activity |

## Definition

`obm_dormancy_days_daily` measures the value-weighted average age, in days, of outputs spent on a given UTC calendar day.

For each spent output `i`, let:

```text
ValueBTC_i
```

be the BTC value of the previous output being spent, and let:

```text
AgeDays_i
```

be the age of that previous output, measured as the elapsed time in days between the block in which the output was created and the block in which it is spent.

Bitcoin Days Destroyed for the day is:

```text
CDD_d = sum_i ValueBTC_i * AgeDays_i
```

Daily spent value is:

```text
SpentValueBTC_d = sum_i ValueBTC_i
```

Dormancy is defined as:

```text
DormancyDays_d = CDD_d / SpentValueBTC_d
```

for dates where `SpentValueBTC_d` is positive.

The unit is:

```text
days
```

because BTC-days divided by BTC leaves days.

The standard OBM daily calendar starts on `2009-01-01`; release exports should not use earlier `--start_date` values.

## Interpretation

`obm_dormancy_days_daily` reports the average age of spent coins, weighted by the BTC value of the spent outputs.

For example, if the only outputs spent on a given day are:

```text
1 BTC aged 10 days
3 BTC aged 20 days
```

then:

```text
CDD = 1 * 10 + 3 * 20 = 70 BTC-days
Spent value = 1 + 3 = 4 BTC
Dormancy = 70 / 4 = 17.5 days
```

This metric is useful for:

- measuring the average age of coins being spent;
- distinguishing high-value recent turnover from movement of older supply;
- studying dormant-coin activation;
- complementing raw Bitcoin Days Destroyed;
- comparing spent value with destroyed coin age;
- analyzing long-term-holder behavior and UTXO-age dynamics.

The metric should not be interpreted as transaction count, payment volume, user activity, or entity-adjusted economic settlement value. It is a value-weighted age measure of spent outputs.

## Relationship with the spent-output indexer

This metric is exported from the table:

```text
daily_aggregates
```

in the SQLite database produced by:

```text
obm_spent_output_indexer.py
```

The relevant source columns are:

```text
cdd_sats_days
spent_value_sats
```

The indexer stores CDD internally as satoshi-days:

```text
cdd_sats_days = sum(value_sats_i * age_days_i)
```

and spent value as satoshis:

```text
spent_value_sats = sum(value_sats_i)
```

Therefore, dormancy can be computed directly as:

```text
dormancy_days = cdd_sats_days / spent_value_sats
```

No conversion factor is needed in the ratio, because both numerator and denominator use satoshis as the value unit. The resulting unit is days.

The exporter does not query Bitcoin Core. It only reads the already generated indexer database and writes a standard OBM CSV file.

## Data format

The CSV file follows the standard OBM schema:

```text
date,series_id,value,unit,frequency,release_version
```

Example:

```csv
date,series_id,value,unit,frequency,release_version
2024-01-01,obm_dormancy_days_daily,8.239184726415,days,daily,OBM v0.1.0
2024-01-02,obm_dormancy_days_daily,7.261904183725,days,daily,OBM v0.1.0
```

When dormancy is undefined because no spent value exists for a date, the value field is written as:

```text
NaN
```

Example:

```csv
date,series_id,value,unit,frequency,release_version
2009-01-01,obm_dormancy_days_daily,NaN,days,daily,OBM v0.1.0
```

### Columns

| Column | Description |
|---|---|
| `date` | UTC calendar date in `YYYY-MM-DD` format |
| `series_id` | Stable OBM identifier: `obm_dormancy_days_daily` |
| `value` | Daily dormancy in days, or `NaN` when undefined |
| `unit` | Measurement unit: `days` |
| `frequency` | Observation frequency: `daily` |
| `release_version` | OBM dataset release version inherited from the indexer metadata |

## Reproducibility

The metric is generated by reading the persistent OBM spent-output indexer database.

For each date in the requested interval, the exporter:

1. opens the SQLite database generated by `obm_spent_output_indexer.py`;
2. verifies that the database metadata identify it as an OBM spent-output indexer database;
3. verifies that the requested ending date is not beyond the maximum processed date recorded by the indexer;
4. reads `cdd_sats_days` and `spent_value_sats` from `daily_aggregates`;
5. computes `cdd_sats_days / spent_value_sats` when `spent_value_sats` is positive;
6. writes `NaN` when `spent_value_sats` is zero or when the date has no row in `daily_aggregates`;
7. writes the resulting time series to CSV using the standard OBM schema;
8. optionally generates a plot, skipping undefined observations.

The blockchain scan, previous-output resolution, spent-value aggregation, and CDD computation are performed by the shared spent-output indexer. This exporter is a deterministic transformation from the indexer database to the OBM CSV format.

## Typical script usage

Generate the CSV file:

```bash
python3 export_obm_dormancy_days_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --output data/daily/obm_dormancy_days_daily.csv
```

Generate the CSV file and a plot:

```bash
python3 export_obm_dormancy_days_daily.py \
  --start_date 2009-01-01 \
  --end_date 2024-01-31 \
  --state_db cache/obm_spent_output_indexer.sqlite \
  --output data/daily/obm_dormancy_days_daily.csv \
  --plot \
  --plot_output figures/obm_dormancy_days_daily.png
```

If `--plot_output` is omitted while `--plot` is used, the plot is saved next to the CSV file with a `.png` extension.

## Command-line arguments

| Argument | Description |
|---|---|
| `--start_date` | Starting UTC date, inclusive, in `YYYY-MM-DD` format |
| `--end_date` | Ending UTC date, inclusive, in `YYYY-MM-DD` format |
| `--state_db` | Path to the SQLite database generated by `obm_spent_output_indexer.py` |
| `--output` | Output CSV file path |
| `--release_version` | Fallback release version if the indexer database does not contain one |
| `--plot` | Generate a plot of the exported series, skipping undefined observations |
| `--plot_output` | Output path for the plot |

If the indexer database contains `release_version` metadata, the exporter uses that value. Otherwise, it uses the fallback value passed through `--release_version`.

## Requirements

The exporter assumes:

- an existing SQLite database generated by `obm_spent_output_indexer.py`;
- Python 3;
- SQLite through Python's standard library;
- `matplotlib`, only if plot generation is requested.

This exporter does not require:

- a running Bitcoin Core node;
- access to the Bitcoin Core JSON-RPC interface;
- direct block scanning;
- direct previous-output reconstruction at export time;
- address extraction;
- user clustering;
- entity identification;
- external price data;
- third-party APIs.

The heavy blockchain processing is performed by the spent-output indexer before this exporter is run.

## Indexer coverage assumption

The OBM spent-output indexer is designed to be built from the Bitcoin genesis block onward. Therefore, this exporter assumes that the indexer database contains a complete historical pass from block height 0 through the maximum processed height recorded in the metadata.

Under this invariant, a missing row in `daily_aggregates` for a requested UTC date does not indicate an unprocessed date. It indicates that no spent-output aggregate was assigned to that date under the indexer's timestamp convention. For `obm_dormancy_days_daily`, such dates are exported as `NaN`, because the spent-value denominator is zero and the ratio is undefined.

Users should not use this exporter with a partially initialized or truncated indexer database unless they first verify that the requested date interval is fully covered.

## Missing-value convention

Dormancy is a ratio:

```text
DormancyDays_d = CDD_d / SpentValueBTC_d
```

If `SpentValueBTC_d` equals zero, the ratio is undefined. In this case, the exporter writes:

```text
NaN
```

This is intentional. A zero value would imply that coins were spent with an average age of zero days. That is not the same as no coins being spent.

The correct conventions are:

```text
CDD_d = 0                    if no coin age was destroyed
SpentValueBTC_d = 0          if no output value was spent
DormancyDays_d = NaN         if SpentValueBTC_d = 0
```

The use of `NaN` preserves the mathematical meaning while remaining compatible with many numeric tools and plotting libraries. Plot generation skips `NaN` observations.

## Precision

The exporter writes defined dormancy values with twelve decimal places:

```text
value = cdd_sats_days / spent_value_sats
```

This is a ratio measured in days. The twelve-decimal output convention preserves more precision than is usually needed for interpretation, while keeping the CSV representation stable and reproducible.

## Aggregation to lower frequencies

Because dormancy is a ratio, monthly dormancy should not be computed mechanically as an arithmetic average of daily dormancy values without explicit justification. A more interpretable monthly version is obtained by first summing monthly CDD and monthly spent value, and then computing:

```text
DormancyDays_m = CDD_m / SpentValueBTC_m
```

for months with positive spent value. This preserves the interpretation of dormancy as the value-weighted average age of spent coins over the month.

## Validation

The following internal checks are performed or recommended:

- verify that `--start_date` is not later than `--end_date`;
- verify that the SQLite state database exists;
- verify that the database metadata contain the expected `indexer_id`;
- verify that the database contains processed-date metadata;
- verify that `--end_date` is not later than the maximum date processed by the indexer;
- verify that every requested date appears exactly once in the output;
- verify that undefined observations are marked as `NaN`, not zero;
- check that all defined dormancy values are non-negative;
- verify that `obm_dormancy_days_daily = obm_cdd_btcxdays_daily / obm_spent_value_btc_daily` for dates with positive spent value;
- compare selected periods with independent public dormancy or coin-age metrics as diagnostics.

External comparisons should be interpreted cautiously because providers may differ in timestamp convention, transferred-value definition, spent-output definition, fractional-day treatment, entity adjustment, change-output treatment, and handling of historical edge cases.

## Relationship with other OBM metrics

This metric is closely related to:

```text
obm_cdd_btcxdays_daily
obm_spent_value_btc_daily
obm_cdd_per_supply_days_daily
```

The main identity is:

```text
obm_dormancy_days_daily =
    obm_cdd_btcxdays_daily /
    obm_spent_value_btc_daily
```

for dates where spent value is positive.

Equivalently:

```text
obm_cdd_btcxdays_daily =
    obm_dormancy_days_daily *
    obm_spent_value_btc_daily
```

for defined observations.

## Known limitations

Take into account that this metric:

- is exported from the OBM spent-output indexer database;
- depends on the correctness and completeness of the indexer run;
- inherits the UTC block-timestamp convention of the indexer;
- inherits the fractional-day age convention used for CDD;
- is undefined when no spent value exists for a date;
- is a raw spent-output metric, not an entity-adjusted measure;
- includes self-transfers, change-related activity, batching, and consolidation transactions through the underlying spent-value and CDD series;
- does not identify users, entities, exchanges, custodians, or payment purpose;
- may change if the underlying indexer definition or release version changes.

Despite these limitations, `obm_dormancy_days_daily` is a useful OBM coin-age series. It provides a transparent value-weighted measure of the average age of spent coins and complements raw CDD and spent-value metrics in the study of dormant supply, long-term-holder behavior, and UTXO-flow dynamics.
